# 루시 카톡형 다중 말풍선 순차 전송 및 연속 자동낭독(Auto-TTS) 구현 계획

루시가 답변할 때 긴 문장을 한 덩어리로 길게 보내는 대신, 실제 단짝 친구가 카카오톡으로 대화하듯 **2~4개의 자연스러운 말풍선**으로 나누어 짧은 시간차로 톡톡 보내도록 개선합니다. 동시에 **자동읽기(Auto-TTS)**가 켜져 있을 때는 쪼개진 여러 말풍선을 중간 끊김이나 중복 없이 처음부터 끝까지 한 호흡으로 매끄럽게 연달아 읽어줍니다.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> **사용자 확정 설계 기준**
> 1. **말풍선 분할 개수 및 전송 연출**: 긴 답변은 문맥과 호흡에 맞춰 **2~4개의 말풍선**으로 분할하며, 첫 말풍선 직후 짧은 간격(약 350~500ms)을 두고 순차적으로 팝업 전송되는 카톡식 라이브 연출을 적용합니다. (아주 짧은 한 줄 답변은 억지로 쪼개지 않고 1개 말풍선으로 자연스럽게 표시합니다.)
> 2. **적용 대화 모드 범위**: 일상 수다 모드뿐만 아니라 **7대 특화 채널 및 PRO 마스터 모드를 포함한 루시 채팅의 모든 대화 모드**에 카톡식 다중 말풍선 분할을 일괄 적용합니다.
> 3. **자동읽기(Auto-TTS) 연속 낭독**: 말풍선이 2~4개로 나뉘어 순차 표시되더라도, 음성 낭독은 각 말풍선이 뜰 때마다 끊기거나 재시작되지 않고 **전체 답변(1번~마지막 말풍선)을 하나의 연속 오디오 큐로 묶어 처음부터 끝까지 자연스럽게 연달아 재생**합니다.

## 1. Overview & Core Concept

기존 루시 채팅은 답변 분량이 길어질수록 하나의 거대한 말풍선 안에 모든 문단이 담겨 메신저 특유의 생동감과 가독성이 떨어졌습니다. 이번 개선을 통해:

- **사람 같은 카톡 티키타카 리듬**: 루시가 공감·도입 멘트, 핵심 통찰/풀이, 따뜻한 응원이나 마무리 질문을 각각 별도의 말풍선(최대 2~4개)으로 나누어 보내어 실제 사람과 카톡하는 듯한 몰입감을 제공합니다.
- **마크다운 및 구조 보존 분할**: 문단 경계, 대화 호흡, 마크다운 블록(리스트·강조구문·인용구 등)이 깨지지 않도록 의미 단위로 스마트하게 분할합니다.
- **원클릭 & 자동 연속 낭독**: 자동읽기(Auto-TTS)는 전체 응답 텍스트를 하나의 통합 오디오 스트림으로 선취(Prefetch) 및 연속 재생하고, 현재 읽고 있는 말풍선 그룹에 음성 재생 인디케이터를 자연스럽게 연동합니다.

## 2. User Experience & Visual Design

### 카톡 스타일 다중 말풍선 그룹 레이아웃
- **첫 번째 말풍선**: 상단에 `Lucy` 프로필 라벨, 활성화된 대화 모드 배지, 활용된 운명학 도구 태그를 표시하고 첫 번째 이야기(공감·인사·핵심 요약)를 전달합니다.
- **이어지는 말풍선 (2~4번째)**: 중복되는 상단 이름표와 모드 배지를 생략하고 컴팩트한 간격(`mt-1.5`)으로 말풍선만 깔끔하게 이어 붙여 실제 카카오톡 연속 메시지 UI와 동일한 시각적 리듬을 구현합니다.
- **타임스탬프 및 추천 액션 바**: 그룹의 마지막 말풍선 하단에 시각(Timestamp), 복사/음성 듣기 액션 버튼, 그리고 전문 모드용 추천 채널/개운 도약 바를 배치하여 화면이 복잡해지지 않도록 정돈합니다.
- **순차 전송 애니메이션**: 새 답변이 도착할 때 첫 말풍선 이후 다음 말풍선들이 짧은 간격으로 부드럽게 등장하며 채팅 스크롤이 자연스럽게 따라 내려갑니다.

## 3. Key Product Decisions & Trade-Offs

- **렌더링 계층 스마트 분할 vs DB 메시지 다중 쪼개기**:
  - 하나의 답변을 데이터베이스에 여러 개의 별도 레코드로 쪼개 저장하면 이전 대화 맥락 압축, 검색, 전체 복사, 추천 질문 추출, 그리고 자동읽기(Auto-TTS) 동기화에서 파편화 문제가 발생할 수 있습니다.
  - 따라서 **데이터 모델(대화 기록 및 AI 컨텍스트)은 1개의 통합 응답 레코드로 무결성을 유지**하되, **AI 프롬프트 지침과 채팅 버블 렌더러에서 의미 단위로 2~4개의 카톡 말풍선 그룹으로 분할 및 순차 노출**하는 하이브리드 아키텍처를 채택합니다.
- **자동읽기(Auto-TTS)와 개별 말풍선 듣기 지원**:
  - 자동읽기(Auto-TTS)는 응답 완료 시 전체 말풍선 텍스트를 하나로 이어서 끊김 없이 연달아 낭독합니다.
  - 사용자가 특정 말풍선을 직접 듣거나 전체 답변 듣기 버튼을 누를 때도 끊김 없는 통합 재생과 개별 복사가 모두 가능하도록 지원합니다.

## 4. Technical Architecture & Data Strategy

```
[사용자 메시지 전송]
       │
       ▼
[루시 AI 응답 생성 (모든 대화 모드 공통)]
  ├─ 프롬프트 지침: 자연스러운 카톡 호흡(2~4개 단락 구분) 유도
  └─ 스트리밍 완료 시 전체 텍스트 확정
       │
       ├──────────────────────────────────────────┐
       ▼                                          ▼
[카톡 다중 말풍선 스마트 분할기]            [연속 Auto-TTS 오디오 파이프라인]
  ├─ 문단/문장 호흡 및 마크다운 블록 분석     ├─ 분할된 2~4개 말풍선 텍스트를
  ├─ 긴 답변을 2~4개의 균형 잡힌 말풍선으로   │  순서대로 결합하여 단일 청크 큐 생성
  │  그룹화 (짧은 문장은 1개 유지)            └─ 첫 말풍선부터 마지막 말풍선까지
  └─ 최신 응답 시 ~400ms 간격 순차 팝업 연출     중복/끊김 없이 1회 연속 재생
```

### 핵심 처리 흐름
1. **카톡 호흡 프롬프트 및 스마트 문단 분할기 (`splitIntoKakaoBubbles`)**:
   - 루시 시스템 프롬프트에 카톡처럼 생각을 2~4개의 자연스러운 호흡(문단)으로 나누어 작성하도록 안내합니다.
   - 클라이언트 분할 유틸리티가 응답 텍스트를 분석하여 코드/인용/목록 블록을 보호하면서 글자 수와 문장 경계에 맞춰 **2~4개의 말풍선 배열**로 일관되게 나눕니다.
2. **순차 말풍선 등장(Staggered Reveal) 컨트롤러**:
   - 방금 생성 완료된 최신 답변의 경우, 분할된 각 말풍선이 짧은 딜레이를 두고 순차적으로 화면에 나타나며 자동 스크롤을 부드럽게 갱신합니다.
   - 이미 지나간 이전 대화 내역은 딜레이 없이 즉시 2~4개의 멀티 말풍선 형태로 렌더링됩니다.
3. **Auto-TTS 무중단 연속 재생 동기화**:
   - 말풍선이 순차적으로 화면에 추가되는 동안 `Auto-TTS` 감시자가 재호출되어 음성이 중복 재생되거나 끊기지 않도록, 응답 ID(`msg.id`) 기준 단일 뮤텍스로 전체 말풍선 내용을 한 번에 끝까지 연속 낭독합니다.
