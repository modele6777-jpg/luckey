# 음성 낭독(TTS) 시 큰 글씨(제목) 및 굵은 글씨(강조어·소제목) 하이라이트 정밀 개선 계획

음성 낭독(TTS)을 실행할 때 **큰 글씨(제목 `h1`~`h6`)**나 **굵은 글씨(`**강조어**`, `<strong>`)**가 포함된 문장에서 하이라이트(형광펜)가 적용되지 않던 문제를 해결하고, **루시 채팅과 7대 채널·핸드북·모달 등 앱 전체 낭독 화면**에서 굵은 글씨가 포함된 문장 전체가 끊김 없이 하나로 자연스럽게 하이라이트되도록 통합 개선합니다.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> 사용자 질의응답을 통해 확정된 핵심 설계 방향입니다.

- **굵은 글씨 포함 문장 하이라이트 단위**: 문장 앞이나 중간에 굵은 글씨(`**소제목**: 본문...` 또는 `오늘은 **사주와 타로**를 통해...`)가 포함되어 있을 때, 굵은 글씨와 일반 글씨가 나뉘지 않고 **해당 문장 전체가 하나의 형광펜으로 자연스럽게 통합 하이라이트**됩니다.
- **적용 범위**: **루시 채팅(`LucyProTypewriter`)**뿐만 아니라 **7대 채널·리바이블 핸드북·모달(`Streamdown`, `TTSHighlightedText`, `TTSHighlightText`) 등 앱 전체 낭독 화면**에 일괄 적용됩니다.

---

## 1. Overview & Core Concept

- **원인 진단 (왜 큰 글씨나 굵은 글씨에서 하이라이트가 누락되었는가?)**
  1. **음성 변환 시 굵은 글씨 강제 줄바꿈 분리**: 음성 전처리기(`prepareNaturalSpeechText`)가 문장 시작 부분의 `**굵은 글씨**:` 패턴을 만나면 강제로 마침표와 줄바꿈(`\n굵은 글씨.\n`)을 삽입해 음성을 두 문장으로 쪼개버리는 반면, 화면의 마크다운 렌더링(`p`, `li`)은 한 문장으로 묶여 있어 길이 비율(60% 기준) 불일치로 하이라이트가 탈락했습니다.
  2. **복합 인라인 노드(`<strong>` + 일반 텍스트) 분리 순회**: 마크다운이 `오늘은 **중요한 전환점**입니다.`를 `["오늘은 ", <strong>"중요한 전환점"</strong>, "입니다."]`와 같이 여러 조각의 자식 노드로 렌더링할 때, 기존 하이라이터가 개별 문자열 조각 단위로만 매칭을 시도하여 여러 문장이 섞인 문단(`p`) 안에서 `<strong>`이 포함된 문장을 통째로 감싸지 못했습니다.
  3. **발음 변환(숫자·기호·영문 약어)과 원문 텍스트 간의 정규화 격차**: 큰 글씨 제목이나 굵은 강조어에 자주 쓰이는 `1. ~ 7.`, `&`, `/`, `%`, `VS`, `PRO`, `MBTI`, 괄호 부연 설명 등이 음성용 한글 발음(`첫째`, `그리고`, `대`, `엠비티아이` 등)으로 바뀐 뒤 원문과 비교될 때 일부 변환 규칙이 매칭 정규화 함수에 빠져 있어 큰 글씨 제목 매칭이 실패했습니다.
  4. **컨테이너 활성화 판별 누락**: `LucyProTypewriter`에서 현재 낭독 중인 말풍선인지 확인할 때 마크다운 기호(`#`, `**`)를 제거하지 않은 원문과 음성 변환 텍스트를 단순 비교하여, 마크다운 기호가 많은 답변일수록 하이라이트 대상에서 제외되는 문제가 있었습니다.

- **핵심 가치**: 어떤 크기의 제목이든, 문장 어디에 굵은 글씨가 들어가 있든 음성 낭독과 동시에 정확하고 부드러운 형광펜 하이라이트가 100% 일치하여 따라갑니다.

## 2. User Experience & Visual Design

- **자연스러운 통합 문장 하이라이팅**
  - **큰 글씨(제목 `h1`~`h6`)**: 번호(`1.`, `2.`), 기호(`·`, `&`, `/`), 괄호, 이모지, 강조 표시가 포함된 큰 제목도 루시가 읽는 순간 제목 전체가 하나의 황금빛 앰버 하이라이트로 선명하게 표시됩니다.
  - **굵은 글씨(`strong`, `b`)가 포함된 문장**:
    - 단일 문장 문단/리스트(예: `- **핵심 조언**: 오늘 오후에는 가벼운 산책으로 기운을 환기해 봐.`): 소제목과 본문이 끊어지지 않고 문장 전체가 한 호흡으로 낭독되며 한 줄 통째로 하이라이트됩니다.
    - 다중 문장 문단(예: 한 문단 안에 2~3개의 문장이 이어지고 그중 한 문장 내부에 `**굵은 강조어**`가 들어간 경우): 인라인 토큰 경계(`<strong>`, `<em>`, `<span>`)를 보존한 채 **해당 문장이 시작하는 지점부터 끝나는 마침표까지(`<strong>` 포함) 하나의 `<mark>`로 매끄럽게 묶어** 하이라이트합니다.
- **테마 및 타이포그래피 조화**
  - 라이트 모드(루시 채팅·키 채널)와 다크 모드(7대 프리즘 채널·핸드북) 각각의 배경 대비에 맞춘 앰버 하이라이트 스타일을 유지하며, 큰 글씨 제목(`h1`~`h6`)에서는 글자 크기와 굵기(`font-bold`)가 축소되지 않도록 `font-weight: inherit` 및 자연스러운 패딩을 적용합니다.

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: 문장 내 `**굵은 글씨**:` 패턴의 호흡 및 문장 일체화**
  - *Chosen Approach*: 줄 전체가 오직 `**독립된 굵은 소제목**`으로만 이루어진 경우에만 독립 문장으로 처리하고, `**굵은 키워드**: 뒤따르는 설명 문장`처럼 한 줄에 이어지는 경우에는 강제 줄바꿈(`\n`) 대신 자연스러운 쉼표 호흡(`, `)으로 연결하여 하나의 문장으로 낭독·하이라이트합니다.
  - *Why*: 사용자가 선택한 "굵은 글씨가 포함된 문장 전체를 하나로 자연스럽게 하이라이트" 기준을 충족하고, 화면의 한 줄 구조와 음성 청크 구조를 1:1로 일치시키기 위함입니다.

- **Decision 2: AST 인라인 노드 병합 기반의 문장 단위 그룹핑 하이라이터 도입**
  - *Chosen Approach*: 문단(`p`, `li`, `blockquote`) 내부에 텍스트와 `<strong>` 등 React 인라인 요소가 섞여 있을 때, 자식 노드 배열을 문장 경계(`.`, `!`, `?`, `\n`) 기준으로 그룹핑하여 각 문장 그룹의 전체 텍스트를 기준으로 매칭한 뒤, 일치하는 문장 그룹 전체를 하나의 `<mark>`로 감쌉니다.
  - *Why*: 한 문단 안에 여러 문장이 있을 때도 `<strong>` 태그가 들어간 특정 문장만 정확히 찾아내어 끊김 없이 하이라이트할 수 있습니다.

## 4. Technical Architecture & Data Strategy

### Architecture & Alignment Pipeline

```
┌──────────────────────────────────────────────────────────────────────────┐
│                     1. Speech Text Normalization                         │
│  - Standalone Bold Line (**Title**)      ──► Independent Sentence        │
│  - Inline Bold Prefix (**Label**: Body)  ──► Single Sentence with Pause  │
└───────────────────────────────────┬──────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                  2. Bidirectional Phonetic Normalizer                    │
│  - Syncs TTS spoken forms (첫째~열째, 에이아이, 프로, 엠비티아이, 대, 퍼센트) │
│    with UI symbols (1.~10., AI, PRO, MBTI, VS, %, &, /, ·, brackets)     │
└───────────────────────────────────┬──────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────────┐
│             3. Holistic & Inline-Aware Sentence Highlighter              │
│  ┌───────────────────────────────┐  ┌──────────────────────────────────┐ │
│  │ Headings (h1~h6) & Single-    │  │ Multi-Sentence Paragraphs with   │ │
│  │ Sentence Blocks               │  │ Inline <strong> / <em> Elements  │ │
│  │ ──► Holistic Full-Node Match  │  │ ──► Sentence-Boundary Grouping   │ │
│  │     & Single <mark> Wrap      │  │     across React Child Nodes     │ │
│  └───────────────────────────────┘  └──────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
```

### Interactive Component & State Mapping
1. **음성 전처리 (`speechText.ts`)**:
   - 독립된 줄 전체가 `**소제목**`인 경우에만 줄바꿈 문장으로 분리하고, 뒤에 텍스트가 이어지는 `**강조어**: 설명...` 또는 문장 중간의 `**강조어**`는 문장을 쪼개지 않고 한 문장으로 유지합니다.
2. **양방향 정규화 및 문장 매칭 엔진 (`TTSHighlightedText.tsx` & `ttsHighlight.tsx`)**:
   - `cleanSentenceForMatching`에서 `prepareNaturalSpeechText`가 수행하는 모든 발음 치환(`프로`↔`pro`, `음성`↔`tts`, `엠비티아이`↔`mbti`, `디엔에이`↔`dna`, `대`↔`vs`, `퍼센트`↔`%`, `그리고`/`또는`/`에서`/`따라서` 등)을 양방향으로 동일하게 정규화합니다.
   - 복합 React 자식 노드(`string` + `<strong>` + `string`)로 구성된 문단에서 마침표(`.`, `!`, `?`, `\n`)를 기준으로 노드들을 문장 단위 세그먼트로 분할·재조립하여, 여러 문장 중 굵은 글씨가 포함된 문장도 100% 정확하게 단일 `<mark>`로 하이라이트합니다.
   - 큰 글씨 제목(`h1`~`h6`) 하이라이트 시 원본 제목의 폰트 굵기와 크기가 그대로 유지되도록 스타일을 보강합니다.
3. **전역 렌더러 일괄 연동 (`LucyProTypewriter.tsx`, `Streamdown.tsx`, `TTSHighlightedText.tsx`)**:
   - `LucyProTypewriter`의 `isCurrentlyRead` 판별 로직을 정규화된 매칭 함수(`cleanSentenceForMatching` / `isSentenceActive`) 기반으로 교체하여 마크다운 기호가 많은 답변에서도 누락 없이 하이라이트를 활성화합니다.
   - `Streamdown` 및 전역 `TTSHighlightedText` 컴포넌트에도 동일한 인라인 그룹핑 하이라이터를 적용하여 루시 채팅, 7대 채널, 핸드북, 모달 전체에서 일관된 하이라이트 경험을 제공합니다.
