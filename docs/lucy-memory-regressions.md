# 기억 오연결·반복 질문 재현 검사 — v1.7.169

새 기능을 추가하기보다 v1.7.168의 후속 기억 검색과 답변 검토에서 오류를 재현했다. 실제 이용자의 사적 대화를 가져오지 않고 가상 발언을 사용했다.

## 수정 전 실패한 재현 사례

| 상황 | 발견한 문제 | 수정 |
| --- | --- | --- |
| 가온회사 기억 뒤 새봄회사 질문 | 새로 명시한 이름을 몰라 예전 가온회사 기억을 함께 검색 | 처음 등장한 이름도 대상 조건에 사용해 다른 대상의 기록 제외 |
| 면접 준비 뒤 ‘취소했어’ | 지시어 없는 짧은 정정은 주제를 상속하지 않아 누락 | 짧은 취소·결과·완료를 앞선 맥락에 연결 |
| ‘그 거북이는 뭘 먹어?’, ‘그 건물 높이는?’ | ‘그거’, ‘그건’으로 잘못 매칭하여 면접 후속으로 취급 | 지시어 뒤 단어 경계와 조사 확인 |
| ‘아까는 고마웠어’ | 기억이 없다는 확인 질문을 유도 | 단순 감사·맞장구를 사건 회상 요청과 구분 |

이 네 재현 검사는 수정 전 실패했고 수정 후 통과했다. ‘다른 회사’처럼 새 이름이 아직 없는 경우와 명시적으로 다른 친구를 소개하는 경우도 기존 인물·회사 기록으로 바꾸지 않도록 검사했다.

## 답변을 표시하기 전 추가 대조

생성에 사용한 동일한 구조화 기억을 검토에도 전달한다. 다음처럼 좁고 명확한 경우를 코드로 대조해, 모델이 잘못 승인하거나 수정안에 같은 오류를 넣어도 표시하지 않는다.

- 회사 하나가 명확한데 ‘어느 회사 면접이야?’처럼 이미 알려준 회사 이름을 다시 질문.
- 사용자가 합격 사실을 말하지 않았는데 ‘합격했잖아’라고 과거 사실처럼 회상. ‘불합격’·질문·조건부 예시는 합격 사실로 바꾸지 않는다.
- 한 회사의 계획을 취소했다고 했는데 ‘아직 면접 준비 중이구나’라고 되돌림. 사용자가 다시 지원을 고려하거나 재개한 경우는 허용한다.

새 회사가 등장했거나 여러 회사가 불분명한 경우에는 필요한 확인 질문을 허용한다. 이름·결정·취소가 복잡하게 섞인 모든 한국어 표현을 증명하는 규칙은 아니며 나머지 의미 판단은 모델 검토에 의존한다. 알려진 정보를 반복해서 묻는 모든 형태를 완전히 막는다고 보장하지 않는다.

## 검증

기억·대화·답변 검토·기존 핵심값 대조 관련 검사 67개를 실행했다. 브라우저 검사는 가상 기억과 통제된 API 응답으로 일반/프로 후속 답변, 잘못된 검토 승인 이후 차단·정상 복구, 검토 중 취소까지 네 상황이 통과했다. 회사의 문화나 선호를 묻는 질문과 취소 여부를 묻는 질문을 이미 알려준 사실로 오인하지 않는 검사도 통과했다. 미검토 초안은 화면과 장기기억에 저장되면 안 된다. 외부 실제 모델의 모든 대화 품질을 검증한 결과와 구분한다.

```sh
node --import tsx --test tests/lucy-conversation-memory.test.ts tests/lucy-memory-reply-checks.test.ts tests/lucy-long-term-memory.test.ts tests/lucy-reply-review.test.ts tests/lucy-critical-facts.test.ts tests/chat-divination.test.ts tests/lucy-chat-page-mode.test.ts
node scripts/test-master-reviewed-chat.mjs --normal --memory
node scripts/test-master-reviewed-chat.mjs --memory
node scripts/test-master-reviewed-chat.mjs --normal --memory --approve-wrong-memory
node scripts/test-master-reviewed-chat.mjs --normal --memory --cancel
```
