# Sites 내부 API 전환 — 1.4.476

## 적용 구조

앱의 별도 AI API 14개 경로를 Sites Worker의 `server/sites-api.ts`에서 직접 처리합니다. 이 경로에는 외부 서버 주소 `LUCKEY_API_ORIGIN`이 필요하지 않습니다. 사용자가 선택한 구성은 Sites 내부 API + 기존 Gemini입니다. Sites 자체 모델이나 무료 AI API로 교체했다고 주장하지 않습니다.

## 검증 결과

- 네이티브 응답 계약·입력 검증·이미지 프록시·WAV·오류 처리 검사 21개 통과.
- 공통 텍스트·스트리밍·JSON 생성 실제 Google 응답 200.
- 일반 생성, 기록 분석, 타로, 세도나, 축복, 감정 추천, 뮤즈·파랑새 도슨트 실제 응답 200.
- 작품 추천에서 Google의 일시적 서버 오류를 한 차례 확인했고, 제한된 재시도와 응답 검증을 추가한 뒤 실제 응답 200 확인. 권한·한도 오류는 재시도하지 않습니다.
- 데일리 BGM은 48초 22,050Hz 스테레오 WAV를 Worker에서 합성하며 Google 키를 요구하지 않습니다.
- 원본 작품 조회와 허용된 원본 이미지 프록시 200 확인. AI 재해석 이미지는 원본과 구분해 표시합니다.
- Gemini 음성은 실제 생성된 PCM을 mono 24,000Hz WAV로 제공하며 일반 낭독·도슨트 엔진의 디코딩 형식을 맞췄습니다.
- Google 이미지 모델 두 종류에서 현재 키가 429 사용 한도 오류를 반환했습니다. 이미지 생성 요청의 라우팅·형식 처리는 구현했고, 한도 오류를 화면에서 숨기지 않습니다. 이미지 생성 기능의 완전한 이용에는 해당 Google 프로젝트의 사용 한도 확보가 필요합니다.

실제 외부 호출은 합성 테스트 문장과 공개 작품 정보만 사용했으며, 사용자 저장 데이터나 프로필 사진을 테스트에 사용하지 않았습니다. 프로필 사진은 텍스트 해석의 컨텍스트에서도 제외합니다. 인증·기존 Sites D1 데이터·공유 범위는 변경하지 않았습니다. 기존 구형 동기화·MCP 서버 경로는 이번 AI API 14개 이관 범위에 포함하지 않습니다. 브라우저 화면에서 직접 재생·조작하는 검사는 별도로 수행하지 않았습니다.

## 운영 설정

런타임 `gemini` 또는 `GEMINI_API_KEY`가 필요합니다. 선택 설정은 `GEMINI_MODEL`, `GEMINI_TTS_MODEL`, `GEMINI_IMAGE_MODEL`입니다. 키는 Worker 안에서만 사용하며 클라이언트 번들에 넣지 않습니다.

## 재검사

`node --import tsx --test tests/sites-api.test.ts`

`scripts/audit-sites-api.mjs <로컬 Worker 경로> <결과 경로> --live-media`는 실제 Google 생성 요청을 사용합니다. 키 설정 JSON은 숨김 표준입력으로만 전달하며, 결과에는 상태·형식 검증만 기록합니다. 미디어 호출이 필요 없으면 `--live-media`를 생략합니다. 운영 동기화·릴레이·초기화 요청은 호출하지 않습니다.

## 1.4.477 추가 경로 점검

미술 화면의 이미지 실패 시 외부 생성 서비스를 직접 요청하던 자동 대체 URL을 제거했습니다. 마스터클래스의 수동 이미지 재생성도 Sites 내부 Gemini API를 사용합니다. 기존 저장 이미지의 출처 감지는 호환성을 유지합니다. 작품 변경 뒤 도착한 이전 생성 결과는 적용하지 않습니다.

채팅의 외부 생성 URL 조립 지침도 제거했으며, 마음 정리 도구 이미지도 `/api/ai/image`의 실제 결과를 사용합니다. 이미지 실패는 텍스트 생성 오류로 묶어 재요청하지 않고 호출 화면으로 전달합니다.
