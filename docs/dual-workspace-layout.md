# 내용 중심 듀얼 작업 영역

`DuoWorkspace`는 컨테이너 안의 실제 콘텐츠 폭이 896px 이상이면 두 열을 사용한다. 기본 구역은 전체 폭이며, 짧고 관련 있는 카드에만 `duo-workspace-card` 또는 `duo-workspace-pair`를 사용한다. 긴 설명과 결과 목록은 전체 폭을 유지한다.

입력·결과 구역은 의미상 그룹을 유지하면서 카드 단위로 배치한다. 빈 결과를 위한 가짜 패널은 표시하지 않는다. 프로필은 기본 정보와 운명 프리뷰를 전체 폭으로, 나머지를 개별 카드로 표시하며 좁은 화면에서는 기존 단계 이동을 사용한다.

`useWideWorkspace(container)`는 같은 컨테이너의 패딩을 제외한 폭을 측정하고 `ResizeObserver`로 갱신한다. 컨테이너가 아직 없거나 서버에서 렌더링할 때는 한 열을 기본으로 한다. 기존 인자 없는 호출도 지원한다.

팝업은 `WorkspacePortal`로 본문에 배치한다. 가장 위 팝업에서 Tab 순환과 Escape 닫기를 처리하고, 닫힌 뒤 이전 포커스를 복원한다. 헤더·스크롤 본문·작업 영역은 분리하고 화면 안전 영역과 동적 높이를 사용한다. 카드 이미지 확대의 기존 포털은 유지한다.

## 검증

- `node --import tsx --test tests/workspace-width.test.ts`
- `npm run lint`
- `npm run build`
- 360·390·768·1024·1440px에서 짧은 카드와 긴 결과, 생성 중·오류·빈 결과의 배치를 확인한다.
- 팝업을 짧은 높이에서도 열어 닫기·저장 버튼과 키보드 포커스를 확인한다.
- 합성 데이터로 공통 레이아웃을 검사하고, 실제 계정의 기록이나 AI 생성 결과를 변경하지 않는다.

API, 저장 키와 데이터 스키마는 변경하지 않는다. 우측 사이드바의 자동 열림 동작과 실제 접이식 화면의 힌지 간격은 유지한다.

## 공통 컴포넌트 브라우저 검사

실제 `DuoWorkspace`, `WorkspacePortal`과 빌드된 앱 CSS에 로컬 합성 데이터를 넣어 검사했다. 360·390·768px는 한 열, 1024·1440px는 두 열로 표시됐으며 전체 폭 해설, 버튼 가로 범위와 가로 스크롤 검사를 통과했다. 생성 중·결과 없음·오류 상태에서는 단독 카드가 전체 폭을 사용했다.

360×420px에서 팝업은 화면 안에 들어왔고 본문만 스크롤됐다. 닫기·저장 버튼, Tab 순환, Escape 닫기, 이전 포커스 복원과 합성 저장 상태를 확인했다. 실제 계정의 모든 생성 결과나 실물 모바일 키보드를 조작한 검사는 포함하지 않는다.

1440px 화면의 200% CSS 확대 렌더링에서는 유효 콘텐츠 폭 681px에 맞춰 한 열로 전환됐고, 전체 폭 해설과 가로 넘침 검사를 통과했다. 이 검사는 브라우저 자체의 확대 설정을 바꾸지 않고 공통 컴포넌트에 확대를 적용한 검사다.
